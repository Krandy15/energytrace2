# EnergyTrace

Electricity theft detection dashboard: ranks accounts by risk score, maps
suspected accounts geographically, and shows per-account usage anomalies.

## Structure

```
EnergyTrace/
├── frontend/   # React + Vite dashboard (works standalone, no backend needed)
├── backend/    # placeholder — no API exists yet, see backend/README.md
└── ai/         # offline scripts that generate the data frontend/ reads
```

**Current state:** only `frontend/` and `ai/` have real code. The frontend
runs entirely on JSON files (generated by the `ai/` scripts or already
committed under `frontend/src/data/` and `frontend/public/`) — there is no
live backend yet, despite the frontend's proxy config anticipating one on
`localhost:8000`. See `backend/README.md` for what that API would need to
expose.

## Quick start (frontend only — this is what actually runs today)

```bash
cd frontend
npm install
npm run dev
```

## Regenerating the demo data

```bash
cd ai/scripts
python generate_mock_nodes.py     # synthetic 400-node demo set
python map_real_data.py           # scores ai/data/raw_dataset.csv into 1000 nodes
```

Both write straight into `frontend/src/data/`, which the frontend imports
directly — see `ai/README.md`.

## Deploying

- **Frontend only (current state):** `cd frontend && npm run build` produces
  a static `dist/` you can deploy to Vercel, Netlify, GitHub Pages, or any
  static host. No environment variables are required for this — the app
  works fully offline against its bundled JSON data.
- **With a real backend:** once `backend/` exists and is deployed somewhere,
  set `VITE_API_URL` in `frontend/.env` (copy `.env.example`) and wire
  `frontend/src/api/client.js` to call it, per `frontend/README.md`.

## Before you push to GitHub

- `frontend/node_modules/`, `frontend/dist/`, and any real `.env` files are
  already excluded via `.gitignore` — don't force-add them.
- The old `dist/` build output from the original export was dropped rather
  than restructured, since build artifacts shouldn't be committed; `npm run
  build` regenerates it.
- `frontend/.env.example` is committed as a template; copy it to `.env`
  locally (git-ignored) before running anything that needs `VITE_API_URL`.

## What changed from the original export

This was reorganized from a flat, mixed-together file dump into the three
folders above, and a few broken cross-file links were fixed along the way so
the app actually works end to end:

- `Dashboard.jsx` imported `./mock_400_nodes.json` from inside `pages/`;
  that file now lives in `src/data/` and the import path was updated.
- `DemoHighlights.jsx` linked to `/accounts/:id`, but the only registered
  route is `/account/:id` (singular) — fixed to match.
- `DemoHighlights` had no route in `App.jsx` at all — added `/demo`.
- `postprocessing` is imported directly in three files but was missing from
  `package.json` (only present as a transitive dependency) — added explicitly
  so `npm install` reliably provides it.
- `ai/scripts/map_real_data.py` had a hardcoded Windows path
  (`D:\hackathon\...`) as its CSV source — replaced with a relative default
  and a `--csv` flag.
- The dataset file `data set.csv` (space in the name) was renamed to
  `raw_dataset.csv` to avoid path-quoting issues in scripts and shells.
